## 3. Recommended Deployment Strategies

### Option A: Direct Root Replacement (Fastest & Zero Data Loss - Recommended)
Since the device has full `su` access, the modded `base.apk` can be swapped directly into the existing app directory without triggering package signature validation:
```bash
# 1. Locate current app directory
APK_PATH=$(adb shell "su -c 'pm path com.amazon.kindle'" | head -n 1 | tr -d '\r' | sed 's/package://')
APK_DIR=$(dirname "$APK_PATH")

# 2. Push modded apk to staging
adb push <modded_base.apk> /data/local/tmp/base_mod.apk

# 3. Swap base.apk in place, fix permissions, and force-stop
adb shell "su -c '
  cp /data/local/tmp/base_mod.apk $APK_DIR/base.apk && \
  chmod 644 $APK_DIR/base.apk && \
  chown system:system $APK_DIR/base.apk && \
  rm /data/local/tmp/base_mod.apk && \
  am force-stop com.amazon.kindle
'"
```

### Option B: Keep-Data Uninstall + Debug-Signed APK Install
If testing standard APK installation:
```bash
# 1. Sign modded APK with bundled debug.keystore:
apksigner sign --ks debug.keystore --ks-pass pass:android --ks-key-alias androiddebugkey --key-pass pass:android <modded_base.apk>

# 2. Uninstall while preserving app data and databases (/data/data/com.amazon.kindle):
adb shell "cmd package uninstall -k com.amazon.kindle"

# 3. Install debug-signed APK:
adb install -r -d <modded_base_signed.apk>
```
