================================================================================
KF8 (libWebCoreKRF.so / libKRF.so) Binary Header & INDX Deep Analysis
================================================================================

1. Summary of Findings & Root Cause for Blank Page:
--------------------------------------------------
Although IKindleDocument.createViewer returned NON-NULL (Viewer successfully created,
format recognized as MOBI8, and native Table of Contents drawer fully populated with all chapters),
the reader rendered a blank white page. Our reverse-engineering and comparison against
the verified working KF8 reference (Rashomon and Other Stories.azw3) revealed the root causes:

a) Fragment Selector Syntax in CNCX (Primary Cause of Blank Rendering):
   - In generated AZW3, CNCX aid string was written as bare '0001'.
   - In verified working KF8 (Rashomon), CNCX aid string is formatted as an XPath selector:
     "P-//*[@aid='1']"
   - Kindle's FragmentLoader / WebCoreViewer uses this selector to find the DOM insertion
     anchor in the skeleton. When given bare '0001', the DOM query fails to find the target node,
     leaving the skeleton with an empty <body></body>, which renders blank white!

b) PalmDB Record Ordering & first_non_book:
   - Generated AZW3 placed image records before SKEL and FRAG (fnb=24 pointing to images).
   - Working KF8 places FRAG, SKEL directly after text records (fnb=39 pointing to FRAG Master INDX),
     and images are placed after SKEL.

c) extra_data_flags (rec0 + 240 / mobi + 224):
   - Generated AZW3 had extra_data_flags = 0.
   - Working KF8 uses extra_data_flags = 1 (or 3) with PalmDoc compression.
