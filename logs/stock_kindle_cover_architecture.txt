1. ARCHITECTURAL OVERVIEW & USER DIRECTIVE
--------------------------------------------------------------------------------

User Architectural Directive:
"The approach to display the cover as part of the book is a mistake. The correct
path is to just take the image and render it differently so you don't have the
difficulty you are having with margins."

Stock Kindle's actual internal implementation proves this insight 100% accurate:
Stock Kindle NEVER displays the cover as a normal reflowable HTML page inside
WebCore's spine flow. In stock Kindle:
1. Cover detection is metadata-driven (PalmDB EXTH 201 image index + DocumentInfo).
2. When the user navigates to the Cover, the rendering engine enters a dedicated
   Cover Page mode.
3. The engine CLEARS all HTML text layout elements (DocumentPage::clear()).
4. The cover image is extracted directly from the binary PalmDB record buffer into
   a standalone native image object (CxImage).
5. The native engine centers the image on a pure black background (#000000) using
   the raw viewport dimensions, completely bypassing WebCore HTML margins (z8.i)
   and suppressing the reading progress footer (0%).
6. On page turn forward, leaveCoverPage() resets the mode flag and restores normal
   HTML text layout and user margins for Chapter 1.
