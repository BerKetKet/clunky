=== STOCK KINDLE SEND-TO-KINDLE (STK) KFX INSPECTION REPORT ===
Date: 2026-11-21
Stock Package: com.amazon.kindle (v8.160.1.0) - Read-Only Inspection
Target Package: com.amazon.kindle.epub ("Folio")

1. Directory Hierarchy & Storage Layout
---------------------------------------
Stock Kindle stores cloud-delivered Send-to-Kindle (STK) personal documents across two primary locations:
a) Main book container storage:
   /sdcard/Android/data/com.amazon.kindle/files/kindle/
   Contains monolithic .kfx files named using Amazon Content Reference (ACR) format:
   `CR!<Base32_ID>.kfx` (e.g., CR!6KYWZNKF153BK4YSK5MTFZ1XN6ZA.kfx, CR!ZTD3FX31BX225B7KRMNC6MN5NFHZ.kfx)
   Also contains metadata/index sidecars:
   - `<timestamp>.index`
   - `.pagination.cache/<hash>` (cached page calculation hashes)

b) Per-ASIN tracking directories:
   /sdcard/Android/data/com.amazon.kindle/files/<ASIN_OR_UUID>/
   - `<ASIN>.ticr` (Typographical/Interactive Content Reading state / position markers)
   - `<ASIN>.ticr.backup`
   - `autocompletecache.ser` (serialized Java search index for in-book search)

c) Internal app databases:
   /data/data/com.amazon.kindle/databases/kindle_library.db
   - Table `KindleContent`: stores ID, TITLE, AUTHOR, STATE ('LOCAL' or 'REMOTE'), CONTENT_TYPE ('PDOC' / 'EBOK')
   - Table `LocalContent`: maps KEY (ID) to FILE_PATH on disk

2. KFX Container Binary Header Analysis
---------------------------------------
Every STK .kfx file begins with the standard Amazon KFX Container format (KFX-CONT v2):
Offset 0x00 - 0x03: 43 4f 4e 54 ("CONT")
Offset 0x04 - 0x05: 02 00 (Container format version 2)
Offset 0x06 - 0x07: Chunk offset table size
Offset 0x08 - 0x09: Chunk header offset
Offset 0x0A - 0x0B: 50 00 / 51 00 / 53 00 (Entity table flags)

Sample Hexdump (CR!ZTD3FX31BX225B7KRMNC6MN5NFHZ.kfx, 242 KB):
00000000: 434f 4e54 0200 4312 0000 c210 0000 5000  CONT..C.......P.
00000010: 0000 ab03 0000 9100 0000 0000 0000 0000  ................
00000020: 0000 4821 0000 0000 0000 bb03 0000 9100  ..H!............
00000030: 0000 4821 0000 0000 0000 cc20 0000 0000  ..H!....... ....

3. Unencrypted Ion / YellowJersey Payload Verification
------------------------------------------------------
Analysis of personal documents sent via Send-to-Kindle reveals:
- Amazon's Send-to-Kindle cloud pipeline converts EPUB -> KFX using Amazon's server-side generator (YJReaderSDK).
- Generator stamp found in KFX metadata:
  `PackageVersion:YJReaderSDK-1.0.x.x GitSHA: c805492 Month-Day:04-22`
  `ApplicationVersion: 20.12.238.0`
- Crucially, personal documents (PDOCs) are NOT encrypted with Amazon DRM.
- Symbol tables and text streams are stored as uncompressed / unencrypted Amazon Ion binary structures:
  * Symbol table: `YJ_symbols`
  * Text blocks: `kfxgen.textBlock`
  * Fragment symbols: `content_1`, `content_2`, `c10-ad`, etc.
  * Resources: `resource/rsrcW0`, `resource/rsrcW1` (JPEG/PNG images stored directly in container)
  * PID mapping: `kfxgen.pidMapWithOffset`
  * Table of Contents: Plaintext ASCII/UTF-8 strings directly parseable (e.g. "Contents", "E01 The Ferryman's Almanac", "T1 Column counts")
